# Активация и деактивация attendance

`POST /control` принимает сообщение Plugin Manager (`schemaVersion: "1.0"`). Старый путь `/platform/control` не поддерживается. Адрес StreamAPI и TLS берутся из серверной конфигурации `attendance.streamapi.*`.

```bash
curl --noproxy '*' --request POST 'http://127.0.0.1:18081/control' \
  --header 'Content-Type: application/json' \
  --data-raw '{
    "schemaVersion":"1.0",
    "activationId":"UUID_FROM_PLUGIN_MANAGER",
    "activationSecret":"SECRET_FROM_PLUGIN_MANAGER",
    "pluginId":"attendance",
    "pluginVersion":"1.0.2",
    "registryId":"local",
    "callId":"RM_REAL_CALL_ID",
    "initialContext":null
  }'
```

ID и секрет должны быть выданы тем Plugin Manager, который проверяет разрешения для StreamAPI. Произвольный UUID с произвольным секретом сервер не авторизует. Менеджер доставляет секрет только backend плагина; публичные API состояния его не раскрывают. Не используйте глобальный ключ Plugin Manager в качестве activationSecret.

## Запуск

Backend хранит обработку по activationId, привязывает её к callId и создаёт отдельный SDK-клиент через `.activation(id, secret)`. Подписка включает `participant.joined`, `participant.left` и `call.ended`; эти события должны быть разрешены манифестом. Для одного звонка допускается одна одновременно работающая активация attendance; другой ID для уже занятого звонка возвращает 409. Разные звонки имеют независимые трекеры, клиенты и подписки.

HTTP 200 возвращается после SDK `onConnected()` с телом:

```json
{"activationId":"...","callId":"RM_...","status":"TRACKING"}
```

`TRACKING` — локальное состояние подписки. Plugin Manager переводит свою запись в `ACTIVE` после успешного ответа. Создание подписки и ожидание заголовков gRPC используют общий бюджет `attendance.activation.start-timeout`. По умолчанию это 4 секунды, в профиле `local` — 2,5 секунды с запасом на CloudPub. Если за это время подписка не готова, плагин возвращает 504 `ACTIVATION_TIMEOUT` и закрывает подписку и SDK-клиент. Плагин пишет в лог итог и длительность обработки `/control` с `activationId`.

Отказ StreamAPI возвращает 502 `ACTIVATION_FAILED` с причиной. Несовместимое сообщение — 400. Повтор с изменёнными параметрами того же ID — 409. Одновременные одинаковые запросы ждут одну подписку. Повтор успешного запуска не создаёт ресурсов заново; после неудачного запуска тот же запрос может начать новую попытку. Дедупликация запусков хранится в памяти процесса. Явно деактивированные ID сохраняются на диске и больше не запускаются, в том числе после перезапуска.

Манифест с `initial-state: ["participants"]` запрашивает начальный состав. Плагин добавляет участников из `initialContext.participants` в `present` при первом подключении к StreamAPI и учитывает их с `trackingSince`. Если контекст отсутствует или список пуст, состав заполняется по событиям StreamAPI.

## Деактивация

Для штатного отключения вызывайте `POST /v1/activations/{activationId}/deactivate` в Plugin Manager с `{"requestedBy":"MODERATOR_ID"}`. Manager переводит запись в `STOPPING` и доставляет на тот же `POST /control`:

```json
{
  "schemaVersion": "1.0",
  "operation": "deactivate",
  "activationId": "UUID_FROM_PLUGIN_MANAGER",
  "callId": "RM_REAL_CALL_ID",
  "pluginId": "attendance",
  "requestedBy": "MODERATOR_ID",
  "activationSecret": "SECRET_FROM_PLUGIN_MANAGER"
}
```

Поля `pluginVersion`, `registryId` и `initialContext` для остановки не нужны. Команда запуска по-прежнему принимается без `operation`; явное `operation: "activate"` также поддерживается. Неизвестная операция возвращает 400 и не создаёт подписку.

Плагин прекращает обработку событий указанной активации, закрывает подписку и SDK-клиент, фиксирует `stoppedAt` и сохраняет итоговую историю. HTTP 200 с `{"activationId":"...","callId":"RM_...","status":"STOPPED"}` возвращается после закрытия ресурсов и успешной записи. Только затем manager может перейти в `STOPPED`. При ошибке хранилища ответ — 503; manager повторяет доставку. Повтор сохраняет исходное время остановки.

Деактивация не завершает сам звонок и не придумывает выход участников: `endedAt` остаётся пустым, открытые периоды в отчёте ограничиваются `stoppedAt` и помечаются как граница учёта. Уже завершившийся или отказавший трекер сохраняет своё итоговое состояние и время. Отчёты доступны через прежние API и архив.

Команды проверяются по паре `activationId` и `callId`, для известной активации также сверяется секрет. Несовпадение возвращает 409. Повтор остановки допустим, в том числе от другого модератора. Команда для старой активации не отключает новую активацию того же звонка. Если запуск ещё не приходил, остановка сохраняет запрет на его запоздалую доставку. Повтор запуска остановленного ID возвращает 503 `ACTIVATION_STOPPED`; для нового запуска manager должен выдать новый `activationId` и секрет.

Запреты хранятся отдельными файлами в `attendance.reports.directory/deactivations`. Они содержат SHA-256 отпечаток секрета, а не сам секрет, и сохраняются после перезапуска и очистки отчётов по retention. Автоматически эти небольшие записи не удаляются, чтобы старые команды не могли снова запустить подписку. Сохраняйте весь каталог `attendance.reports.directory` на постоянном томе.

`/control` предназначен для доверенного Plugin Manager. Плагин не проверяет роль `requestedBy` в платформе звонков; проверку модератора выполняет вызывающий backend. Доступ к управляющему маршруту должен быть ограничен инфраструктурой.

## Диагностика

Профиль `local` включает DEBUG для attendance и пишет логи в консоль и `backend/logs/attendance.log` при запуске из каталога `backend`. Файл ротируется при достижении 10 МБ, архивы хранятся за 7 дней с общим лимитом 100 МБ. Путь можно изменить через `logging.file.name` в `config/application-local.yml`. Изменения конфигурации применяются после перезапуска приложения.

Для других профилей DEBUG можно включить аргументом `--logging.level.ru.itmo.plugins.attendance=DEBUG` в **Program arguments** IntelliJ или при запуске из PowerShell.

```powershell
.\gradlew.bat bootRun --args='--spring.profiles.active=local'
```

Строки `HTTP #… started` и `HTTP #… completed` показывают начало и конец запроса, его путь, статус и длительность. По ним видно, дошли ли до backend `GET /actuator/health` и `POST /control`. По `activationId` можно сопоставить обработку команды с запуском подписки StreamAPI и логами Plugin Manager. Тела HTTP-запросов, заголовки и параметры URL в эти логи не попадают.

## Чтение состояния

```bash
curl --noproxy '*' 'http://127.0.0.1:18081/api/calls/RM_REAL_CALL_ID/participants'
```


Активация не зависит от открытой страницы и не удаляется по UI idle-timeout. Деактивация, `call.ended`, окончательная ошибка SDK и завершение процесса закрывают подписку и клиент. Снимок штатно отключённого плагина удаляется при очередной очистке; завершённый/ошибочный снимок — по failed-retention. Сохранённые отчёты доступны до истечения `attendance.reports.retention`.

Локальная страница: `http://127.0.0.1:18081/?callId=RM_REAL_CALL_ID`. Она только читает готовую обработку.

Манифест должен содержать control-url с путём `/control`. Настройка внешнего HTTPS-доступа для серверного менеджера в эту доработку не входит.
